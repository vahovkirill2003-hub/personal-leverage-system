# KICKOFF — запуск реализации PLS в Claude Code

## Подготовка репозитория (один раз, до первого запуска Claude Code)

```bash
mkdir pls && cd pls
git init
# распакуйте сюда содержимое комплекта: CLAUDE.md, KICKOFF.md, MANIFEST.md, docs/
git add .
git commit -m "docs: accepted specification package (see MANIFEST.md)"
```

Проверка целостности (по желанию, но в духе проекта):
```bash
cd docs && sha256sum -c ../MANIFEST.md --ignore-missing
```

## Запуск Claude Code

В каталоге `pls` выполните `claude` (CLI/Desktop; варианты установки — https://docs.claude.com/en/docs/claude-code/overview). Подтвердите доверие к папке. `/init` запускать НЕ нужно — CLAUDE.md уже готов и будет прочитан автоматически.

## Первое сообщение (скопируйте целиком)

Прочитай CLAUDE.md, просмотри действующий docs/25-implementation-task-breakdown-v0.1.md и учти решения журнала стадии docs/26-implementation-stage-decision-log-v0.md.

Подтверди одним коротким сообщением: (1) нормативную иерархию и запреты из CLAUDE.md; (2) что docs/ неприкосновенен; (3) первую задачу и её DoD.

Затем выполни TB-01: репозиторий уже инициализирован и содержит docs/ — создай структуру модульного монолита по компонентам архитектуры §3.1, pyproject с pinned lockfile, CI (lint, pytest, migration dry-run заглушкой, сборка одного OCI image), базовый Makefile. Кода доменной логики не пиши. Заверши отчётом: что создано, как запустить проверки, что вошло в DoD.

## Ритм дальнейшей работы

1. Одна задача TB-NN за раз; следующая — только после вашего «дальше».
2. Для задач размера L сначала просите план (Plan Mode / «сначала план, без правок»), утверждайте, потом реализация.
3. Смотрите diff перед принятием правок; коммит после зелёного DoD.
4. `/clear` между задачами — контекст каждой задачи чистый, память проекта несёт CLAUDE.md.
5. Ошибку исправили — добавьте правило в «Накопленные правила проекта» CLAUDE.md.
6. Любой конфликт со спецификациями Claude Code обязан вернуть вам как дефект — принесите его в чат проектирования, там решим и зафиксируем: решения стадии реализации ведутся в журнале `docs/26` начиная с `PLS-067` (журнал `16` остаётся журналом стадии спецификаций).
7. Действующие версии документов перечислены в CLAUDE.md. Принятые файлы `docs/` не редактируются: изменение оформляется новой версией файла рядом, а её SHA-256 добавляется в MANIFEST.md.

## Контрольные точки для чата проектирования

Возвращайтесь в чат проектирования (этот проект) на гейтах фаз `docs/22` §4: конец фазы 1 (mock-ядро зелёное), перед фазой 3 (evals), перед TB-37 (независимый аудит) и при любом дефекте спецификаций — там ведётся журнал и принимаются решения.
