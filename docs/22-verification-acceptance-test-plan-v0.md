## 0. Принципы

1. Тест — гейт, а не документация: класс со статусом не-PASS блокирует соответствующую фазу (раздел 4), а не «фиксируется как риск».
2. Каждый класс проверяет невозможность обхода правила (command, retry, concurrency, restart, model output), а не наличие текста в коде.
3. Фикстуры не содержат реальных персональных данных Кирилла (правило сред `21` §1, `20` §6); персональный контекст имитируется синтетикой.
4. Пороги model-evals — эксплуатационные настройки пилота: заданы здесь стартово, меняются записью журнала стадии с обоснованием, никогда — задним числом к уже пройденному гейту (`PLS-022/050` по аналогии).
