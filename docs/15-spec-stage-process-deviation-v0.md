# Personal Leverage System
## Specification Stage Process Deviation v0: упрощённый контур проверки документов стадии спецификаций

**Статус:** принято решением Кирилла  
**Дата:** 6 августа 2026  
**Область:** порядок проверки и приёмки семи документов стадии технических спецификаций (`14`–`…`), разрешённой актом `13`  
**За рамками:** продуктовый baseline, архитектура v1.1, гейты продуктового workflow PLS — они не изменяются

## 1. Решение

Для документов стадии технических спецификаций Кирилл 6 августа 2026 явно утвердил упрощённый контур: **проверка и пользовательская приёмка выполняются в одном рабочем чате**, без отдельного аудиторского чата на каждый документ.

## 2. Признанное отклонение

Отклонение от практики, применявшейся к продуктовому пакету и архитектуре (отдельный независимый аудит с File Integrity Gate на документ): проверяющая роль в упрощённом контуре может совпадать с автором черновика. Это осознанно принятая потеря независимости на уровне отдельного документа.

## 3. Компенсирующие меры (обязательные)

1. Проверка каждого документа выполняется как отдельный письменный проход с поимёнными находками и их разрешением до приёмки; «проверено» без находок или без объяснения их отсутствия не принимается.
2. Каждый документ получает манифест (байты, SHA-256) при каждом предъявлении; правки до приёмки повышают минорную версию с changelog.
3. Кирилл остаётся единственным акцептором каждого документа; приёмка — только явным подтверждением.
4. **Перед task breakdown обязателен один сводный независимый аудит всего пакета семи спецификаций** в отдельном чате с полным File Integrity Gate — независимость восстанавливается на границе стадии, где её ценность максимальна. Без вердикта `PASS` или `PASS WITH REQUIRED CORRECTIONS` этого сводного аудита task breakdown не начинается.
5. Обязательства, маршрутизированные актом `13` (`AAR-R1`, `AAR-R2`, `AAR-N1`), сохраняют силу и проверяются сводным аудитом отдельно.

## 4. Границы

Отклонение действует только для стадии спецификаций. Продуктовые гейты PLS (TR → SA → UA внутри workflow продукта) им не затрагиваются. Отклонение прекращается сводным аудитом п. 3.4 либо отдельным решением Кирилла.
