## PLS-067 — Распределение тестового класса T05 по задачам реализации

**Связь:** уточняет применение `22` §1 (класс T05) и `22` §4 (гейты фаз) и task breakdown `25`. Продуктовых решений не изменяет; ни одну запись `10` не заменяет и не уточняет.

### Решение

Тестовый класс T05 «Конкурентные команды» (`22` §1) состоит из четырёх независимых сценариев, механизмы которых принадлежат разным задачам реализации. Владение закрепляется так:

| Часть T05 | Владелец | Механизм |
|---|---|---|
| гонка версий | **TB-05** | транзакционный протокол `17` §3: `SELECT … FOR UPDATE`, проверка `expected_case_version`, UNIQUE `(case_id, case_version_after)` |
| parallel callbacks | **TB-16** | callback-протокол одной транзакцией: `decision_intent.token_hash` + CAS `pending→consumed` (`14` §4) |
| гонки applied | **TB-19** | partial unique `applied = true` per attempt (`14` §4) |
| двойной timer claim | **TB-29** | durable timers, claim по lease, `timer.firing_idempotency_key` (`14` §4) |

Из этого следует:

1. DoD каждой задачи включает **только** закреплённую за ней часть T05.
2. Части, принадлежащие ещё не начатым задачам, **не являются дефектом** завершённой задачи и не блокируют её приёмку.
3. До закрытия всех четырёх частей класс T05 имеет статус **`PARTIAL`** с явным перечнем закрытых и незакрытых частей в отчётности.
4. Полный **`PASS`** T05 наступает только при одновременном зелёном результате всех четырёх частей **на одном релизе** и фиксируется записью настоящего журнала, а не отчётом исполнителя отдельной задачи.

Критерий PASS класса из `22` §1 — «Ровно один эффект; вторые получают conflict/прежний outcome» — не изменяется и применяется к каждой части отдельно.

### Влияние на фазовые гейты

Текст `22` §4 **не изменяется**, и гейт не ослабляется. Формулировка «Подключение реальных моделей к гейтам — T01–T09, T11, T20 PASS на mock-контуре» читается как требование **полного** PASS T05 в смысле п. 4 выше.

Операционное следствие фиксируется явно:

- перед подключением реальных моделей к гейтам должен существовать полный PASS T05;
- поэтому части, принадлежащие **TB-16**, **TB-19** и **TB-29**, должны быть выполнены до этого гейта, даже если сами задачи перечислены в более поздних тематических фазах `25` (TB-16 — фаза 2, TB-19 — фаза 3, TB-29 — фаза 5);
- размещение задачи в разделе фазы `25` не отменяет её зависимостей и не позволяет обойти более ранний фазовый гейт: тематические разделы группируют работу по предмету, а не задают исчерпывающий порядок относительно гейтов.

Владельцы частей T05 находятся **в разных фазах** — это распределение между фазами, а не внутри одной фазы. Формулировка «распределение внутри одной фазы» ошибочна и не должна использоваться при ссылках на настоящее решение.

### Обоснование

`22` §1 задаёт T05 как единый класс по природе проверяемого свойства (конкурентность), а не по слою реализации. Механизмы четырёх сценариев появляются в разные фазы `25`, поэтому единый неделимый DoD либо принуждает исполнителя к преждевременной реализации чужих задач в обход порядка зависимостей, либо оставляет завершённую задачу формально незакрытой без содержательной причины.

Распределение сохраняет полноту класса как гейта: ни один сценарий не исчезает, критерий PASS не смягчается, гейт `22` §4 не сжимается. Изменяется только адресация работы и момент объявления полного PASS.

Прецедент дробления уже присутствовал в `25` v0 (строка TB-19: «T05 (гонки applied)») без соответствующей пометки в строке TB-05, что и породило расхождение. Настоящее решение делает дробление явным правилом и устраняет умолчание.

### Порядок фиксации полного PASS T05

Полный PASS объявляется новой записью настоящего журнала. Запись обязана назвать: идентификатор релиза и CI-run, в котором зелены все четыре части одновременно; перечень тестов по каждой части; подтверждение, что критерий `22` §1 выполнен для каждой части отдельно. До появления такой записи любое утверждение «T05 PASS» в отчётности задач считается ошибочным; корректная формулировка — `T05 PARTIAL` с перечнем.
